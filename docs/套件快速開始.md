# SiteGuard 0.3.0

這是可受控試用的網站資源防護閘道。使用 Python 安裝包管理 Docker，接在既有網站前方；網站不必導入 SDK，也不需要雲端 API key。

需要 Python 3.11 以上、已啟動的 Docker 與 Compose。macOS／Colima 已完成部署測試；Linux 容器完成安裝及設定生成，完整 Linux 主機與 WSL2 部署仍需現場驗收。

## 安裝與啟動

解壓安裝包，在 wheel 所在目錄執行：

```sh
python3 -m venv .siteguard-venv
.siteguard-venv/bin/python -m pip install ./siteguard_gateway-0.3.0-py3-none-any.whl
.siteguard-venv/bin/siteguard init --upstream http://host.docker.internal:3000
.siteguard-venv/bin/siteguard check
.siteguard-venv/bin/siteguard up
.siteguard-venv/bin/siteguard status
```

將 `3000` 改成你的原站埠；Colima 用 `host.lima.internal`，各部署指令加 `--docker-context 你的context名稱`。既有容器服務則在 `siteguard.yaml` 設定 `upstream.url` 與 `upstream.network`，加入原站的 Docker 網路。首次啟動需要下載固定版本的映像及依賴。

預設只監聽 `127.0.0.1:8088`、使用 `observe`。開啟此位址驗證網站功能，再將原本的 HTTPS／反向代理指向它。若前方已終結 HTTPS，設定 `listener.forwarded_proto: https`。只有確定前方代理身分時才設定精確的 `trusted_proxy_cidrs`。

確認正常流量與路由容量後，把 `mode` 改成 `enforce`，重新執行 `up`。將耗資源路由的並行額度預留在較小範圍，可保留其他路由的處理能力。WebSocket／SSE／長串流路由須明確設定 `streaming: true`。詳細設定見附帶的 `docs/網站安裝與操作.md`。

## 網站入口防火牆

0.3.0 新增全站 IP／CIDR 允許與封鎖清單，支援 IPv4／IPv6、封鎖優先與 observe 影子規則。設定見 `docs/網站入口防火牆.md`，完整範例見 `examples/siteguard-firewall.yaml`。此功能控制經過 SiteGuard 的網站請求，不會設定主機 SSH、UDP 或出站防火牆。

## 新增資安防護

0.2.0 提供敏感檔案／危險方法封鎖、管理路徑 CIDR 白名單及安全標頭。指定小型 API 可額外啟用私鑰與特定 token 的回應檢查；設定與限制見 `docs/資安防護功能.md`。observe 不掃描回應，改為 enforce 並重新 up 才生效。

## 更新與回復

```sh
.siteguard-venv/bin/siteguard metrics --format prometheus
.siteguard-venv/bin/siteguard logs --tail 100
.siteguard-venv/bin/siteguard up
.siteguard-venv/bin/siteguard rollback
.siteguard-venv/bin/siteguard down
```

每個站點使用不同 `name` 和部署目錄；保留同一目錄操作更新與回復。候選版本先經 Envoy 原生驗證，啟動失敗會嘗試還原。快照不包含原站資料或外部憑證內容。`status` 就緒代表代理及限流程序健康，仍須實際請求原站。

## 已驗證與限制

0.3.0 本輪通過 135 項自動化測試、51 項原生防火牆案例，並重驗 36 項資安及 17 項 Python 網站功能。

0.2.0 本輪通過 117 項自動化測試、56 項原生資安案例及 17 項 Python 網站功能回歸。包含 HTTP/2 洩漏阻擋、scanner 故障時拒絕與普通路由保持可用；新增內容掃描尚未做生產負載效能驗收。

0.1.0 歷史基線通過 72 項自動化測試、Python／Node 網站協定測試、自有 TLS 憑證驗證，以及 Nginx 私有網路接入與故障回復。普通內容大小限制另測 HTTP/1、chunked、HTTP/2 單／多 DATA frame；支援正確的 100 Continue 上傳握手。

受控 CPU 過載樣本中，24 筆訂單的準時完成數從 3 提高到 24，同時拒絕更多耗資源請求。正常流量樣本中兩條路徑皆 40／40 成功，本機 p95 從 1.967 ms 增為 7.067 ms。這些是有限測試結果，不代表所有網站的收益或延遲。

本版不提供跨副本共用額度、頻寬型 DDoS 清洗、自動容量調校或自動憑證續期。限流程序重啟會重建配額；執行模式下該程序故障會回 503。接入真實站點前，需驗證登入、交易、回呼、上傳、串流與合法請求的拒絕代價。

安裝包內 `SHA256SUMS` 可核對檔案完整性，`verification-summary.json` 記錄驗證範圍與原始證據位置；完整原始證據保存在開發專案中。
